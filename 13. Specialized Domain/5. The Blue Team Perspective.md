# The Blue Team Perspective — Cheat Sheet

## 1. SOC Operations

- **L1:** Alert triage, classify, escalate.
    
- **L2:** Investigate incidents, scope impact, coordinate containment.
    
- **L3:** Threat hunting, advanced forensics, detection engineering.
    
- **MTTD:** Mean Time to Detect.
    
- **MTTR:** Mean Time to Respond.
    
- **Alert fatigue:** Excessive false positives cause analysts to miss real threats.
    

## 2. SIEM & Splunk

**SIEM:** Centralises logs, normalises events, correlates activity, and generates alerts.

Key Splunk fields:

- `index` — data container.
    
- `sourcetype` — log format.
    
- `source` — originating file/input.
    
- `host` — event-generating system.
    
- `_time` — event timestamp.
    
- `_raw` — original event text.
    

**Important:** Set the time picker to `All time` for the room's BOTSv1 dataset (August 2016).

### Essential SPL

```
index=botsv1 | stats count by sourcetype
```

Count events by log type.

```
index=botsv1 sourcetype=WinEventLog:Security | head 10
```

View sample Windows Security events.

```
index=botsv1 sourcetype=WinEventLog:Security | timechart span=1h count
```

Find unusual event-volume spikes.

## 3. Windows Event IDs

|Event ID|Meaning|
|---|---|
|`4624`|Successful logon|
|`4625`|Failed logon|
|`4672`|Special privileges assigned|
|`4720`|User account created|
|`4732`|Added to local security group|
|`4688`|Process created|
|`7045`|New service installed|
|`1102`|Security audit log cleared|

**Suspicious patterns:** Repeated failed logons, unusual privileged logons, unexpected service installations, suspicious parent-child processes, or cleared audit logs.

## 4. Attack Detection — SPL Queries

### Detect high-volume IPS alerts

```
index=botsv1 sourcetype=fgt_utm subtype=ips
| stats count by srcip
| sort -count
| head 1
```

### Detect directory brute-forcing

```
index=botsv1 sourcetype=iis sc_status=404
| stats count by c_ip
| where count > 100
| sort -count
```

### Detect suspicious service installations

```
index=botsv1 sourcetype=WinEventLog:System EventCode=7045
| table _time, Service_Name, Service_File_Name
```

### Detect audit log clearing

```
index=botsv1 sourcetype=WinEventLog:Security EventCode=1102
```

### Investigate process creation

```
index=botsv1 sourcetype=WinEventLog:Security EventCode=4688
| table _time, New_Process_Name, Creator_Process_Name
| head 20
```

## 5. Incident Response

**NIST SP 800-61 Rev. 2:**

1. Preparation
    
2. Detection and Analysis
    
3. Containment, Eradication and Recovery
    
4. Post-Incident Activity
    

**SANS PICERL:** Preparation → Identification → Containment → Eradication → Recovery → Lessons Learned.

## 6. Threat Intelligence

**MITRE ATT&CK hierarchy:**

- **Tactic:** Why the attacker acts.
    
- **Technique:** How the attacker achieves a goal.
    
- **Sub-technique:** Specific method.
    
- **Procedure:** Real-world implementation.
    

|Attack|ATT&CK ID|
|---|---|
|Password guessing|`T1110.001`|
|Network service discovery|`T1046`|
|Web wordlist scanning|`T1595.003`|
|SMB lateral movement|`T1021.002`|
|Clear Windows event logs|`T1070.001`|
|Command and scripting interpreter|`T1059`|

**Pyramid of Pain:** Hashes → IP addresses → Domain names → Network/host artifacts → Tools → TTPs. Detecting attacker behaviour and TTPs generally causes more disruption than blocking individual indicators.

## 7. Wayne Corp Investigation Workflow

### Step 1 — Identify the primary external source

```
index=botsv1 sourcetype=suricata NOT src_ip=192.168.* NOT src_ip=10.*
| stats count by src_ip
| sort -count
| head 1
```

### Step 2 — Find the targeted POST endpoint

Replace `<attacker_ip>` with the identified IP.

```
index=botsv1 sourcetype=iis c_ip=<attacker_ip> cs_method=POST
| stats count by cs_uri_stem
| sort -count
| head 1
```

### Step 3 — Confirm reconnaissance

```
index=botsv1 sourcetype=iis c_ip=<attacker_ip> sc_status=404
| stats count
```

### Step 4 — Check Windows authentication

```
index=botsv1 sourcetype=WinEventLog:Security (EventCode=4624 OR EventCode=4625) <attacker_ip>
| stats count by EventCode
```

**Core investigation technique:** Alert → identify source IP → pivot across log sources → correlate events → reconstruct timeline → map to ATT&CK → determine incident scope and response.

## 8. Red, Blue & Purple Teams
