

## 1. Software Development Models

|Model|Key idea|
|---|---|
|**Waterfall**|Sequential stages; changes late in development are difficult.|
|**Agile**|Iterative development; adapts to changing requirements.|
|**DevOps**|Combines development and operations through collaboration and automation.|
|**DevSecOps**|Integrates security throughout the DevOps lifecycle.|

## 2. DevOps — Key Concepts

- **CI/CD:** Automates code integration, testing, and delivery/deployment.
    
- **Infrastructure as Code (IaC):** Provisions infrastructure using code. Tools: Terraform, Vagrant.
    
- **Configuration Management:** Maintains consistent system configurations.
    
- **Orchestration:** Automates and coordinates workflows.
    
- **Monitoring:** Tracks system health, performance, and failures.
    
- **Microservices:** Breaks applications into smaller, independent services.
    

## 3. Shifting Left

**Shifting Left = Security testing early in development instead of waiting until deployment.**

Benefits:

- Detect vulnerabilities earlier.
    
- Reduce remediation costs.
    
- Avoid late-stage rework and deployment delays.
    

## 4. DevSecOps Practices

- Integrate automated security tests into CI/CD pipelines.
    
- Use code analysis and vulnerability scanning early.
    
- Make security a shared responsibility.
    
- Provide developers visibility into findings and remediation steps.
    
- Prioritise vulnerabilities according to risk.
    
- Use isolated sandboxes for testing.
    

## 5. DevSecOps Challenges

- **Security silos:** Security teams work separately from developers.
    
- **Poor visibility:** Teams cannot easily see or prioritise security issues.
    
- **Rigid processes:** Excessive approval steps slow development.
    

**Goal:** Make security automated, visible, collaborative, and flexible.
