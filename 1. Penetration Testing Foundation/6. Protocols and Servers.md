Several protocols commonly used across networks:

- FTP — File Transfer Protocol
- POP3 — Post Office Protocol 3
- SMTP — Simple Mail Transfer Protocol
- IMAP — Internet Message Access Protocol
- HTTP — Hypertext Transfer Protocol


1. FTP is used to transfer files between a client and server.
**Connections & Ports:**

- **TCP 21** → Control connection (commands, login, etc.)
    
- **TCP 20** → Data connection in **Active FTP**  
    _(Server uses port 20 as the source port to connect back to the client.)_
    
- **Passive FTP** → Data connection uses a random free dynamic port chosen by the server.  
    _(Client connects to that port for file transfer.)_


Command syntax:

```
ftp TARGET_IP
```

Example:

```
ftp 10.10.10.10
```

Important commands:

```
SYST     → Server system type
PASV     → Switch to passive mode
STAT     → Server status
ASCII    → Transfer text files
BINARY   → Transfer binary files
```

Anonymous login:

```
Username: anonymous
Password: anything / email address
```


2. SMTP is used to send and transfer email between mail systems.

Email flow:

```
MUA → MSA → MTA → MDA → MUA
```

Ports:

```
25   → Server-to-server SMTP
587  → Mail submission
465  → SMTP with implicit TLS
```

Command syntax:

```
telnet TARGET_IP 25
```

Example:

```
telnet 10.10.10.10 25
```

Important commands:

```
EHLO / HELO   → Identify yourself
VRFY          → Check whether a mailbox/user exists
EXPN          → Expand a mailing list
MAIL FROM     → Specify sender
RCPT TO       → Specify recipient
DATA          → Enter email content
QUIT          → Close connection
```



3. POP3 is used to retrieve/download emails from a mail server.

Ports:

```
110   → POP3
995   → POP3 over TLS
```

Important commands:

```
USER    → Specify username
PASS    → Authenticate with password
STAT    → Show mailbox status
LIST    → List emails
RETR    → Retrieve an email
DELE    → Delete an email
QUIT    → Exit
```

Command:

```
telnet TARGET_IP 110
```



4. IMAP is used to access and manage emails while keeping them stored on the mail server; unlike POP3, it keeps email synchronized across multiple devices.

Ports:

```
143   → IMAP
993   → IMAPS (TLS)
```

Important commands:

```
LOGIN          → Authenticate
LIST           → List mailboxes
SELECT INBOX   → Open mailbox
EXAMINE INBOX  → Open mailbox read-only
FETCH          → Retrieve email data
SEARCH         → Search emails
STORE          → Modify email flags
LOGOUT         → Exit
```

Command:

```
telnet TARGET_IP 143
```

1. A sniffing attack captures network packets and can expose credentials or other data when the protocol sends information in cleartext.

Common tools:

- Tcpdump → CLI packet capture and analysis
- Wireshark → GUI-based packet capture and protocol analysis
- Tshark → CLI version of Wireshark, useful for scripting

Practical example — capturing POP3 traffic:

```
sudo tcpdump port 110 -A
```

- `port 110` → capture POP3 traffic
- `-A` → display packet contents in ASCII

You may see cleartext data such as:

```
USER frank
PASS D2xc9CgD
```

Other useful commands:

```
sudo tcpdump host 10.20.30.148 -A
sudo tcpdump port 80 -A
sudo tcpdump port 21 -A
sudo tcpdump -w capture.pcap
tcpdump -r capture.pcap -A
```

Wireshark filter:

```
pop
```

The key idea: cleartext traffic can expose exactly what is being transmitted.


2. A MITM attack occurs when an attacker positions themselves between two communicating parties, allowing them to intercept or modify traffic when authentication and integrity are not properly protected.

Common techniques:

- ARP Spoofing → Redirects local network traffic through the attacker.
- DNS Spoofing → Redirects victims to an attacker-controlled destination.
- Rogue Access Point → Routes victim traffic through a malicious Wi-Fi network.
- BGP Hijacking → Redirects traffic at the internet routing level.

Tools:

- Bettercap → ARP/DNS spoofing and traffic interception.
- Ettercap → MITM attacks on LANs.
- mitmproxy → Inspect and modify HTTP/HTTPS traffic.
- Responder → Captures authentication attempts via LLMNR/NBT-NS.


3. TLS encrypts communication between systems and protects data from being read or modified in transit.

Important:

```
DoT       → DNS over TLS → 853
DoH       → DNS over HTTPS → 443
TLS 1.2   → Widely deployed TLS version
TLS 1.3   → Newer TLS version with a faster handshake
STARTTLS  → Upgrades a plaintext connection to TLS
```

Common applications:

```
HTTP  → HTTPS
FTP   → FTPS
SMTP  → TLS/STARTTLS
POP3  → POP3S
IMAP  → IMAPS
```

HTTPS flow:

```
TCP → TLS → HTTP
```


4. SSH provides encrypted remote access to a system.

Port:

```
TCP 22
```

Command syntax:

```
ssh username@IP
```

Example:

```
ssh user@10.10.10.10
```

Important switches:

```
-p  → Specify port
-i  → Specify private key
-J  → Use a jump host
-L  → Local port forwarding
-D  → SOCKS proxy
```

Remote Login
```
ssh USER@IP
scp USER@IP:/path/file .
scp file USER@IP:/path/
rsync -avz -e ssh local/ USER@IP:/remote/
sftp USER@IP
```

- `ssh` → remote login
- `scp` → remote → local / local → remote file transfer
- `rsync` → file/directory synchronization over SSH
- `sftp` → secure file transfer


5. Hydra is used to automate password attacks against network authentication services.

Command syntax:

```
hydra -l USER -P WORDLIST TARGET SERVICE
```

Example:

```
hydra -l admin -P passwords.txt 10.10.10.10 ssh
```

Important switches:

```
-l   → Single username
-L   → Username list
-p   → Single password
-P   → Password list
-s   → Specify port
-v   → Verbose
-V   → Show each attempt
-t   → Number of parallel tasks
-f   → Stop after finding valid credentials
```
