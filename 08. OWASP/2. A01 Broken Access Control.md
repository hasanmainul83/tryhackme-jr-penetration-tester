
Server fails to enforce who can access or modify what.

## Core Patterns

- IDOR → `/user/6` → `/user/7`
    
- Horizontal → User A → User B
    
- Vertical → User → Admin
    
- Forced browsing → Access `/admin` directly
    
- Method tampering → Access via unexpected HTTP method
    
- Parameter tampering → `role=user` → `role=admin`
    
- CSRF → Trick an authenticated browser into sending an unwanted request
    
- SSRF → Server accesses internal resources
    

## Modern Bypasses 

**CORS misconfiguration**

```
curl -i -H "Origin: https://evil.com" https://TARGET/api/user
```

Check whether an untrusted origin can read sensitive, authenticated responses in a browser.

**Path bypass**

```
/admin      → 403
/admin/     → 200
/admin/.    → 200
/admin%2f   → 200
/./admin/   → 200
```

Test whether path normalization differences bypass access controls. Results depend on the server and configuration.

**Method tampering**

```
curl -i -X POST https://TARGET/admin
curl -i -X PUT https://TARGET/admin
```

Check whether changing the HTTP method bypasses authorization.

## Testing

- Low-privilege session:
    

```
curl -i -b "SESSION=USER_A" https://TARGET/api/users/7
```

- **Tool:** Autorize (Burp Suite) — replay requests using a low-privilege session to test access to resources requiring higher privileges. Investigate unauthorized `200 OK` responses.
    

## Core Rule

Enforce authorization server-side on every request. Deny by default and grant access only when explicitly permitted.

**Note:** A `200 OK` response or permissive CORS headers alone do not prove a vulnerability. Verify whether unauthorized access to sensitive data or functionality is actually possible.
