
Untrusted input reaches an interpreter and becomes executable syntax.

## Common Types

- **SQLi** → Manipulate database queries.
    
- **XSS** → Execute JavaScript in a victim's browser.
    
- **Command Injection** → Execute OS commands.
    
- **NoSQLi** → Manipulate NoSQL queries.
    
- **SSTI** → Inject expressions into template engines.
    
- **LDAP Injection** → Manipulate directory queries.
    
- **ORM Injection** → Manipulate ORM-generated queries.
    
- **EL/OGNL Injection** → Abuse expression languages.
    

## Quick Checks

```
SQLi:      ' OR 1=1 --
Command:   ; whoami
XSS:       <script>alert(1)</script>
SSTI:      {{7*7}}
NoSQLi:    {"$ne": ""}
LDAP:      *)(uid=*))(|(uid=*
```

## Prevention

- Use parameterized queries and safe APIs.
    
- Validate input server-side.
    
- Escape output for its specific context.
    
- Never concatenate untrusted input into queries or commands.
    

## Mindset

Does user input remain data, or does it become executable syntax?
