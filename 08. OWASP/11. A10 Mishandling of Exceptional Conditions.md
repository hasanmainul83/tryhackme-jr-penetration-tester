
The application handles unexpected situations incorrectly, potentially causing security checks to be skipped, data leaks, or unsafe behavior.

## Common Examples

- Missing parameters or unexpected input
    
- Race conditions
    
- Null handling errors
    
- Privilege-check failures
    
- Fail-open behavior (security check fails, but access is granted)
    
- Sensitive error messages
    

## Quick Checks

```
# Missing parameter
curl -i "https://TARGET/api/user"

# Invalid value
curl -i "https://TARGET/api/user?id=INVALID"

# Unexpected method
curl -i -X DELETE "https://TARGET/api/user/1"

# Malformed input
curl -i -X POST -H "Content-Type: application/json" \
-d '{"user_id":null}' https://TARGET/api/user
```

## Look For

- Unhandled exceptions and `500` errors
    
- Stack traces exposing internal details
    
- Unsafe defaults or invalid application states
    
- Authorization checks skipped on error paths
    
- Fail-open behavior
    
- Execution continuing after a security check fails
    

## Prevention

- Fail securely; deny access when checks fail.
    
- Handle exceptions without continuing in an invalid state.
    
- Validate missing, null, and unexpected inputs.
    
- Return generic errors; log details securely.
    
- Clean up resources on every execution path.
    
- Test edge cases and race conditions.
    

## Mindset

What happens when the application encounters an unexpected condition? Does it fail securely, or does it leak data or skip security checks?
