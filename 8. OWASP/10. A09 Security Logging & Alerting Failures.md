
Security events aren't properly logged, monitored, or alerted on, allowing attacks to go unnoticed.

## Look For

- Missing login success/failure logs
    
- Password or MFA changes
    
- Privilege changes and admin actions
    
- High-value transactions
    
- Access-control failures
    
- Input-validation failures
    
- Suspicious API activity
    

## Quick Check

```
grep -Ei 'login|failed|admin|password|role|delete' app.log
```

## Test Flow

```
Trigger test attack
→ Check logs
→ Check alerts
→ Verify source IP and timestamp
→ Identify affected account
```

Also check whether security scanners such as Burp Suite or ZAP trigger alerts.

## Real-World Example

**Snowflake campaign (2024)** → Attackers used stolen credentials to access customer environments. Missing MFA and insufficient monitoring increased risk.

## Prevention

- Log security-relevant events.
    
- Centralize logs in a SIEM (Splunk, Elastic, Sentinel).
    
- Alert on repeated failures and suspicious activity.
    
- Protect logs against tampering and deletion.
    
- Never log passwords, tokens, or other secrets.
    

## Mindset

Will defenders know when an attack happens?
