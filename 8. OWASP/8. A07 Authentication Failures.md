
The application fails to reliably verify a user's identity or maintain secure sessions.

## Look For

- Username enumeration (different messages, status codes, or timing)
    
- Weak passwords and missing rate limits
    
- Session fixation or predictable session IDs
    
- Broken password reset flows
    
- Cookie manipulation
    
- MFA bypasses or weak fallback methods
    
- Hybrid password attacks (`Password1!` → `Password2!`)


## Quick Test

```
curl -s -X POST -d "username=admin&password=x" https://TARGET/login
```

Compare valid vs. invalid usernames:

- Status code
    
- Response size and message
    
- Response timing

## Real-World Examples

- **BigBear 2.0** → AiTM phishing platform targeting Microsoft 365 and stealing credentials and session cookies to bypass MFA.
    
- **ARToken** → Phishing platform targeting Microsoft 365 authentication tokens and Primary Refresh Tokens (PRTs).
    

## Prevention

- Enforce phishing-resistant MFA (FIDO2/WebAuthn).
    
- Rate-limit login and password-reset attempts.
    
- Rotate session IDs after login; invalidate sessions on logout.
    
- Use adaptive password hashing (Argon2, scrypt).
    
- Never trust client-side authentication data.
    
- Monitor suspicious logins and token reuse.
    

## Mindset

Can I make the application believe I am someone I'm not?
