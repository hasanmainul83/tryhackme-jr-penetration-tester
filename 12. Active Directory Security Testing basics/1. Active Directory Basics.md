
## 1. AD Fundamentals

Active Directory (AD) centrally manages domain users, computers, groups, and policies, and AD DS stores information about those domain objects. The DC is the server that provides AD authentication and directory services, and the KDC runs on it. A security principal is an identity that can be authenticated and assigned permissions, such as a user, computer, or group.

**Machine accounts:** Machine accounts are computer accounts whose names end in `$`, e.g. `ROOTDC$`, and their passwords are rotated automatically.

## 2. Important Domain Groups

| Group             | Main privilege                                                                                                                                                 |
| ----------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Domain Admins     | Full admin control over the domain. Can log on to DCs.                                                                                                         |
| Enterprise Admins | Full admin control across every domain in the forest. Only exists in the forest root domain; members are automatically added to Domain Admins in every domain. |
| Server Operators  | On DCs only: Can log on, back up/restore files, start/stop services, and shut down. Cannot change security settings.                                           |
| Backup Operators  | Can back up/restore files, bypassing normal file permissions (`SeBackup` / `SeRestore`).                                                                       |
| Account Operators | Can create/modify most user and group accounts. Cannot modify Domain Admins, Enterprise Admins, Administrators, or DC computer accounts.                       |

## 3. OUs vs Security Groups

**Organizational Units (OUs)**

- Organize users and computers.
    
- Apply Group Policy Objects (GPOs).
    
- An AD object belongs to one OU or container at a time.
    

**Security Groups**

- Grant permissions to resources.
    
- Can contain users, computers, or other groups.
    
- A user can belong to multiple groups.
    

**Default containers/OUs:** `Builtin`, `Computers`, `Domain Controllers`, `Users`, `Managed Service Accounts`.

**Security concept:** OUs organize and apply policy; groups grant access.

## 4. Authentication

### Kerberos — Default in modern AD

When a user logs in to the domain, the client contacts the DC, where the KDC verifies their identity and issues a TGT. When the user needs to access a specific service, they send the TGT and the service's SPN to the TGS. The TGS provides a service ticket, which the user presents to the service server to gain access.

### NetNTLM — Challenge-response

1. Client requests authentication.
    
2. Server sends a random challenge.
    
3. Client returns a response derived from authentication data and the challenge.
    
4. For domain accounts, the server forwards the information to a DC for verification.
    
5. The authentication result is returned.
    

The password itself is not sent over the network. Local accounts can instead be verified against the local machine's SAM.

## 5. Domains, Trees, Forests & Trusts

Domain: An administrative boundary containing users, computers, groups, and policies.

Tree: Multiple domains connected through a hierarchical DNS namespace, e.g. `thm.loc → emea.thm.loc`.

Forest: One or more domain trees that share a common schema, configuration, and Global Catalog. Different trees can use different namespaces.

Trust: A relationship that allows identities from one domain or forest to be authenticated for access to resources in another.

|Trust type|Meaning|
|---|---|
|One-way|Only one side trusts the other.|
|Two-way|Both domains trust each other.|
|Parent/child in same forest|Automatically established as a two-way, transitive trust.|

Trust direction: If A trusts B, users from B can be authenticated by A and granted access to resources in A — not automatically the other way around.

Important: Trust does not grant resource permissions by itself. The user must still have the required authorization to access the resource.

## 9. Delegation

**Delegation** is when you give someone **specific admin rights over one OU** — without making them Domain Admin.

It lets a normal user or group do **one particular task** (like resetting passwords) **only in one particular place** (like the Bankers OU) — and nothing else.

Delegation = **limited power, limited area.** Least privilege in action.

## 6. Group Policy Objects (GPOs)

GPO (Group Policy Object): A collection of settings used to centrally manage user and computer configurations in an Active Directory domain.

GPO Link: Attaches a GPO to a Site, Domain, or OU (Organizational Unit). A GPO can be linked to multiple locations.

Inheritance: GPOs linked to a parent OU are inherited by its child OUs unless inheritance is blocked.

Security Filtering: Controls which users or computers can apply a GPO. Default = `Authenticated Users` (authenticated users and computers).

SYSVOL: A shared folder on Domain Controllers that stores Group Policy files, templates, and scripts. The GPO's directory/configuration information is stored in Active Directory.

GPO Refresh: `gpupdate /force` forces the computer and user to reprocess Group Policy settings. Some changes require a logoff or restart.

GPO Processing Order: `LSDOU`

- L – Local
    
- S – Site
    
- D – Domain
    
- OU – Organizational Unit
    

Policies are processed in this order, with later policies generally taking precedence when settings conflict.

### Give a Group Local Administrator Rights on Servers

Objective: Add the `Product Admins` domain group to the local `Administrators` group on all targeted servers.

Path:

`Computer Configuration → Policies → Windows Settings → Security Settings → Restricted Groups`

Steps:

1. Create a new GPO.
    
2. Open Restricted Groups.
    
3. Add the `Product Admins` domain group.
    
4. Under This group is a member of, add the local `Administrators` group.
    
5. Link the GPO to the `Servers` OU.
    

Result: Members of `Product Admins` receive local administrator privileges on the targeted servers.

### Important Interview Gotcha: Restricted Groups

Restricted Groups has two configuration options:

|Option|What it does|
|---|---|
|Members of this group|Defines the exact membership of a group. Members not listed can be removed.|
|This group is a member of|Adds the specified group to another group without defining the target group's entire membership.|

Remember: When using Members of this group, list every intended member. Otherwise, existing administrators who aren't listed may be removed.

### Useful commands

| Command                   | Purpose                                             |
| ------------------------- | --------------------------------------------------- |
| `gpupdate /force`         | Forces Group Policy refresh.                        |
| `gpresult /r`             | Displays applied Group Policy information.          |
| `gpresult /h report.html` | Generates an HTML report of applied Group Policies. |


**11. Organize Domain Computers**

Newly joined non-DC computers land in the default `Computers` container — no organization, one policy for all.

Useful OU layout:

text

TBM.THM.LOC
├── Workstations
├── Servers
├── Domain Controllers
└── Department OUs

Separate OUs let you apply different GPOs to workstations, servers, and departments.

DCs are the most sensitive — they hold AD directory data and credential-related secrets. Keep them in their own OU with tight, DC-specific policies only.

Rule: default `Computers` container = no control. OUs = separate policies per computer type.

## Core Workflow

**Understand the domain → Identify users, groups, and OUs → Check authentication and trusts → Review delegation and GPOs → Trace group membership to resource permissions.**
